# 프로젝트 현황 (2026-11-10 기준)

팀원과 AI 코딩 도구가 "지금 어디까지 됐는지" 파악하는 문서. 작업 규칙은 루트 `AGENTS.md`를 따른다.
상태가 바뀌면 이 문서를 고친 사람이 맨 위 날짜와 해당 항목을 함께 고친다.

## 1. 사이트

- 주소: http://54.253.247.179 (AWS EC2, Nginx)
- 메뉴
  - 홈: 핵심 지표 카드 4개(최근 월 방문객 카드에 12개월 추이선), 최근 방문 흐름, 주요 관광 시장
  - 부산 관광 한눈에: 방문객 추이, 카드 소비, 구군별 현황, 업종별 소비
  - 국가별 관광: 국가 비교, 국가별 상세, 계절성
  - 관광수요 전망: M1 기준 예측과 80%, 95% 예측 범위, 롤링 검증 정확도
  - 분석 리포트: 기간과 국가를 골라 만드는 자동 요약 보고서
  - 부산 행사 캘린더: 부산 MICE 플랫폼 공식 일정
  - 프로젝트 소개
  - 챗봇 "홀리모올리" (오른쪽 아래 버튼)
- 공통 기능: 본문 바로가기, PC 메뉴 줄 고정, 링크 복사, 인쇄 버튼과 인쇄 전용 화면, 잘못된 주소 안내(404), 푸터에 업데이트 시각과 커밋 번호 표시

## 3. 지금 데이터 상태 (중요)

- 화면 숫자는 아직 **예시 데이터**다. 실제 데이터랩 수치와 연결되지 않았다. 화면에 "예시 자료" 배지가 붙어 있다.
  - 예시 데이터 위치: `frontend/src/data/*Mock.js`, `frontend/src/data/visitorDemo.js`
  - 실데이터를 넣는 통로: `frontend/src/data/tourismOverviewData.js`의 `acquireData()` 한 곳
  - 주의: 홈 화면은 `visitorDemo.js`를 직접 읽는다. 실데이터 연결 때 함께 고쳐야 한다.
- 데이터 팀이 수집한 실제 자료는 `sources/results/`에 있다 (예: `외국인_업종_국적별_관광소비_및_방문.csv`, 구 16개 x 국적 24개 x 업종 x 월, 2018-01 ~ 2026-08).
  - 확인 필요: 이 파일의 금액 단위, 카드 소비인지 간편결제 기준인지

## 4. 알려진 문제

| 문제 | 상태 |
| --- | --- |
| 부산 행사 캘린더 고장 | 해결 (11월 10일, PR #5). 10월 14일 무렵부터의 503은 부산 MICE 사이트 인증서가 GlobalSign GCC R6에서 R46 계열로 바뀐 것이 원인. 원본 장애 시 마지막 정상 자료를 최대 7일간 표시. 인증서 변경 시 `frontend/server/certs/README.md` 참고 |
| 상태 확인 API 오표시 | 해결. `/api/mice/health`는 `status`와 함께 `source`(`ok`, `stale`, `failing`, `unknown`), `lastSuccessAt`, `staleMonths`, `lastError` 제공 |
| 챗봇, 리포트 AI 생성 꺼짐 | 원인 확인. 서버에 `.env.server`(AI 키 파일)가 없어 미설정 상태이며 고장은 아님. 비용 확인 후 활성화 여부 결정 필요 |
| 서버 주소 바뀔 수 있음 | 고정 IP 미설정. 서버를 중지했다 켜면 주소가 바뀌며, 재부팅은 괜찮음 |
| 서버 디스크 여유 적음 | 6.7GB 중 정리 후 약 77% 사용. 서버에 VS Code Remote-SSH나 Codex 사용 금지 |
| 저장소 공개 상태 | 팀원 이름, 연락처가 든 발표 자료가 공개됨. 비공개 전환 검토 필요 |

## 5. 정해진 것

- 11월 9일: 대시보드 코드를 이 저장소 `frontend/`로 옮김 (예전 저장소 bibikhue/front_code의 커밋 기록 포함)
- 11월 9일: FastAPI 공용 뼈대 추가 (PR #3). `backend/main.py`에 기능 5개 라우터를 `/api/v1/<기능>`으로 연결했으며, 각 담당자는 `backend/<기능>/router.py`를 채운다. FastAPI 서버는 아직 배포하지 않았다.
- 11월 9~10일: HolyMolllly 기준 배포 전환과 자동 배포 적용. 서버의 `~/holymolly`에는 `frontend/`와 `backend/`만 부분 체크아웃한다. `frontend/` 변경이 main에 push되면 GitHub Actions가 lint, test, build를 검사하고, 통과하면 `deploy.sh`를 실행한다. 검사에 실패하면 배포하지 않는다. 수동 재배포는 Actions 탭의 Run workflow를 사용한다.
  - 팀원은 각자 맡은 부분을 main에 직접 올린다. 팀원은 서버 키를 받거나 서버에 접속하지 않는다. 배포 전용 키는 GitHub Secrets(`EC2_HOST`, `EC2_USER`, `EC2_SSH_KEY`)에만 있고 배포 스크립트 실행으로 제한된다.
  - 서버 보안 그룹의 5173번 포트는 닫았다. 22번(SSH)은 자동 배포용으로 열려 있으며 비밀번호 접속 없이 키로만 접속한다.
