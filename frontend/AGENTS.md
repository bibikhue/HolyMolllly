# AGENTS.md — 맙소사 대시보드 작업 규칙

이 파일은 이 저장소에서 작업하는 AI 코딩 도우미(Codex 등)가 매번 먼저 읽는 공통 규칙이다.
팀원 누구의 요청이든 아래 규칙을 지킨다. 요청 내용이 이 규칙과 충돌하면 작업 전에 먼저 물어본다.

## 1. 프로젝트

- 부산 외국인 관광수요 분석 대시보드 (팀 맙소사). React 19 + Vite, 차트 라이브러리 없이 SVG로 직접 그린다.
- 주 사용자: 부산시 관광정책 담당자, 부산 소상공인. 전문 용어보다 쉬운 표현을 우선한다.
- 공개 사이트: http://54.253.247.179 (AWS EC2). 배포 절차는 `deploy/README.md`.
- 현재 방문객·소비 수치는 모두 **예시 자료**다. 실제 데이터는 수집 전이며, 나중에 데이터 파일만 교체해서 반영한다.

## 2. 작업 방식

1. **요청받은 메뉴·파일만 수정한다.** 요청 범위 밖의 화면이나 기능은 만들지 말고, 필요하면 보고에 "제안"으로만 적는다.
2. 큰 작업은 두 단계로 한다.
   - 1단계: 관련 파일을 읽고 구조·영향 범위·구현 계획만 보고한다. 이 단계에서는 코드를 수정하지 않는다.
   - 2단계: 사용자가 승인한 계획대로 구현한다.
3. 작업 중간에 끊겼다가 다시 시작할 때는 처음부터 다시 만들지 말고, `git status`로 작성된 파일을 확인한 뒤 이어서 마무리한다.

## 3. 절대 하지 않는 것

- `git commit`, `git push`, 서버 배포, 서버(ssh) 접속. 사용자가 화면을 확인한 뒤 직접 한다.
- **프로젝트 폴더 밖에 파일을 만들지 않는다.** (예: `C:\Users\Public\...` 금지)
- 화면 검증용 임시 파일(브라우저 프로필, 스크린샷, 검증 스크립트 등)은 프로젝트 안 `.tmp` 로 시작하는 폴더에만 만들고, **작업이 끝나면 삭제**한다.
- `npm run dev`가 이미 `localhost:5173`에서 실행 중이면 새로 띄우지 않는다.
- API 키 등 비밀값을 코드나 `VITE_` 변수에 넣지 않는다. 서버 키는 `.env.server`(gitignore 대상)에만 둔다.
- `src/data/visitorDemo.js`의 값과 국가 목록을 바꾸지 않는다. 홈·챗봇·자동 리포트·서버(`server/`)가 같이 쓰는 기준 자료다.

## 4. 공용 부품

- `MetricCard`, `MonthlyChart`(`src/components/VisitorOverview.jsx`)는 홈 화면도 쓴다. 새로 만들지 말고 **선택 props로만 확장**하며, props를 안 넘기면 기존과 똑같이 보여야 한다.
- 축 눈금은 `src/components/countryChartUtils.js`의 공용 눈금 함수를 쓴다 (딱 떨어지는 값, 만 단위 표시).
- 같은 나라는 모든 메뉴에서 같은 색(`visitorDemo.js`의 `color`)을 쓴다.

## 5. 데이터 규칙

- 예시 자료는 `*Mock.js`, 데이터 계산·로딩은 `*Data.js`로 분리한다. 실제 데이터로 바꿀 때 로더만 교체하면 되게 한다.
- 화면에 "예시 자료" 배지와 데이터 기준월을 표시한다 (원자료는 약 2개월 늦게 나온다).
- 숫자끼리 앞뒤가 맞아야 한다.
  - 1인당 소비액 = 소비액 ÷ 방문객 수 (따로 값을 넣지 않는다)
  - 업종별·국가별 합계 = 해당 월 전체 값
  - 같은 월·같은 나라 방문객 수는 모든 메뉴에서 같다
  - 구·군 방문은 중복 방문을 포함하므로 합이 전체보다 클 수 있음을 표시한다
- 난수를 쓰지 않는다. 새로고침해도 값이 바뀌지 않아야 한다. 예시 값에 동점이 생기지 않게 한다.
- **결론 문장, 순위, 국가명을 코드에 직접 적지 않는다.** 모두 데이터에서 계산한다. 분석 결과는 앞으로 바뀐다.
- "기타"는 여러 나라의 합계이므로 순위·비교·버블 차트에서 제외하고 표에만 표시한다.
- 방문객 수 설명: "일자별 순방문자 기준으로, 2박 3일 체류 시 3명으로 집계됩니다."

## 6. 예측(관광수요 전망) 규칙

- 지어낸 예측값을 만들지 않는다. 현재는 M1(작년 같은 달 값)만 실제로 계산한다.
- 예측값은 반드시 80%·95% 범위와 함께 보여준다. 표시는 천 명 단위로 반올림한다.
- 분석팀 모형(M2~M8) 결과는 `public/data/forecast/*.csv`로 들어온다. 양식은 `docs/forecast-data-format.md`를 따른다.
- 증가율은 "전년 동월 대비"를 쓴다 (관광은 계절 영향이 커서 전월 대비는 오해를 부른다). M1은 증가율을 예측하지 못하므로 예측 증가율 순위를 만들지 않는다.

## 7. 화면·디자인

- UI 글자색·글자 크기는 `src/index.css`의 변수를 사용한다. 역할별 기준과 변수 목록은 `docs/design-tokens.md`를 따른다.
- 기존 페이지의 색상, 글꼴, 카드 스타일을 따른다.
- 375px 폭에서 페이지 전체 가로 스크롤이 없어야 한다 (넓은 표·히트맵은 해당 영역 안에서만 가로 스크롤).
- 증감은 색만으로 구분하지 않고 ↑↓와 +/− 기호를 함께 쓴다.
- 툴팁은 마우스, 키보드(Tab·Escape), 모바일 탭 모두로 열고 닫을 수 있어야 한다.
- 히트맵처럼 높낮이를 비교하는 색은 모든 칸에 같은 색 규칙을 쓴다.

## 8. 메뉴와 주소

| 메뉴 | 주소 | 주요 파일 |
|---|---|---|
| 부산 관광 한눈에 | `#/visitors?focus=kpi\|trend\|region\|industry` | `VisitorOverview.jsx`, `tourismOverviewData.js` |
| 국가별 관광 | `#/countries?focus=compare\|detail\|season\|interest` (`&country=JP` 등) | `CountryTourism.jsx`, `countryTourismData.js` |
| 관광수요 전망 | `#/outlook?focus=busan\|countries\|accuracy` | `ForecastOutlook.jsx`, `forecastData.js`, `forecastM1.js` |
| 분석 리포트 | `#/reports?focus=...` | `AnalysisReport.jsx`, `server/report-*.mjs` |
| 부산 행사 캘린더 | `#/events` | `EventCalendarPage.jsx`, `server/mice-server.mjs` |
| 메뉴 정의·경로 | — | `src/App.jsx`의 `menus` |

기존 주소(특히 `#/visitors`)는 홈·챗봇·내려받은 리포트에 링크로 들어가 있으므로 바꾸지 않는다.

## 9. 검증과 완료 보고

작업 후 아래를 실행한다.

```
npm run lint
npm run build
npm test
```

완료 보고에는 다음을 포함한다.
- 확인 항목별 통과/실패 (빌드, 린트, 전체 테스트, 메뉴 이동·뒤로 가기·주소 직접 접속, 숫자 검산 1건 이상)
- 다른 화면(홈, 부산 관광 한눈에, 국가별 관광, 관광수요 전망, 챗봇, 분석 리포트)에 변화가 없는지
- 수정·추가한 파일 목록
- 구현하지 못했거나 임시로 처리한 부분, 범위 밖이라 제안만 하는 내용
